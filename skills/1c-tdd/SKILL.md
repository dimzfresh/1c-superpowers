# TDD для 1С

Предмет — изменение поведения в BSL/XML, где результат можно проверить до или сразу после правки. Цикл: **красный → зелёный → рефакторинг** в границах задачи плана.

## Когда открывать

- Новая или меняющаяся логика: проведение, расчёт, обменный контур, общий модуль.
- Роутер направил по «сначала тест», «TDD», «напиши тест», «Vanessa», «YAxUnit».
- `1c-executing-plans` в задаче явно требует проверяемого поведения.

Не открывать для чисто косметического переименования без смены поведения — достаточно синтаксиса и review по diff.

## Шаги по порядку

1. **Шлагбаум репо.** Запустить `python3 <каталог скилла 1c-verification>/scripts/find_checks.py <корень проекта>`.
   - Есть **«можно запускать сценарии (TDD)»** с Vanessa / `.feature` — **ветка VA**.
   - Есть TDD-метка с **YAxUnit** / `tests/Test*.bsl` / `yaxunit.json` — **ветка YAxUnit**.
   - Нет TDD-меток и нет согласованного ожидаемого поведения — **ветка без оракула**.
   - `vanessa-runner.json` / `env.json` «не запускать из ревью» — из **review** базу не грузить; для TDD — только известная команда проекта.
2. **Оракул.** Зафиксировать до кода: сценарий Vanessa / тест YAxUnit / ручной вход→результат.
3. **Красный → зелёный → рефакторинг** в границах задачи плана.
4. **Передача.** К `1c-executing-plans`; перед сдачей — `1c-verification`, сводка — `1c-review`. Зелёный прогон закрывает **этот** оракул, не весь MR.

**Ветка VA** (`.feature`, vanessa-automation.json, …):

1. Команда прогона из README/CI (не выдумывать).
2. Красный → минимальный BSL → зелёный.
3. В ответе: команда, код возврата/хвост лога.

**Ветка YAxUnit** (`yaxunit.json`, каталог `tests` с `Test*.bsl`, упоминание YAxUnit):

1. Команда прогона модульных тестов из README/CI проекта. Базовая форма запуска: `1cv8c ENTERPRISE /IBName <база> /N <пользователь> /C RunUnitTests=<yaxunit.json>`; расширение YAxUnit в базе без безопасного режима. Свою команду не изобретать.
2. Красный тест (или новый тест на поведение) → минимальный production-код → зелёный.
3. Не подменять Vanessa-сценарием, если в репо только YAxUnit — и наоборот.

**Ветка без оракула:**

**Стоп.** Спросить автора: VA, YAxUnit или ручной сценарий. Код «на глаз» не писать. Не обещать поднять фреймворк «из коробки», если find_checks его не видит.

## Стоп и запреты

- Нет оракула и нет TDD-метки — **стоп**.
- Зелёный тест ≠ вердикт сдачи (`1c-review`).
- Не расширять scope чужими модулями.
- Не запускать из ревью то, что помечено «не запускать из ревью».

## Что отдать

- **1c-executing-plans / человеку:** оракул (VA или YAxUnit), красный/зелёный, команда.
- **1c-review:** diff после verify, если затронуты проведение/обмен/CFE.

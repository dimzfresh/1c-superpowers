# Диагностика 1c-superpowers

Предмет — transcript агента или пользователя: какие скиллы открывались, какие фразы триггерили роутер, был ли verify перед «готово». Юрисдикция: не пересматривать весь diff заново — для кода открыть нужный процессный скилл.

## Когда открывать

- «Скиллы не срабатывают», «роутер сломан», «ответ без verify», «написал проверено без review».
- Повтор ошибки после «используй superpowers».

## Фазы (ожидаемая цепочка)

| Фаза | Скилл | Признак пропуска |
|---|---|---|
| Маршрут | `using-1c-superpowers` | Ответ по 1С без упоминания открытого скилла |
| Идея / план | `1c-brainstorming`, `1c-writing-plans` | Код до согласованного плана |
| Реализация | `1c-executing-plans`, `1c-tdd` | Большой diff без тестового контура |
| Отладка | `1c-systematic-debugging` | Правки наугад без гипотезы и факта |
| Шлагбаум | `1c-verification` | «Проверено», «готово», «CI зелёный» без свежих фактов |
| Сводка | `1c-review` | Вердикт или список замечаний не от review-скилла |
| Finish | `1c-finish-branch` | Merge без verify + review |

Специализированные: `1c-extension`, `1c-update`, `1c-exchange` — когда diff или фраза указывает на контур.

## Шаги по порядку

1. **Transcript.** Прочитать последние сообщения: запрос пользователя, открытые skill, ключевые фразы агента.
2. **Улики.** Выписать **строками** цитаты: «написал проверено без find_checks», «нет 1c-review в цепочке», «diff есть, открыт только brainstorming».
3. **Пропуск.** Назвать одну главную пропущенную фазу и скилл для повтора **сейчас**.
4. **Не чинить роутер кодом** без задачи — сначала воспроизвести фразу из `scenarios/routing-phrases.md` репозитория плагина.

Учебный transcript «роутер молчал» (ответ с BSL и «замечаний нет» без скиллов): `scenarios/diagnose-router-silent.md` репозитория плагина.

## Стоп и запреты

- Не выдавать вердикт по diff без `1c-review`.
- Не обвинять «сломан плагин», пока не проверен `using-1c-superpowers` и путь установки из README.
- Не писать сводку замечаний по коду — направить в `1c-review` после открытия нужного процесса.

## Что отдать review и человеку

- **1c-review:** только если уже есть diff и запрос на проверку — после устранения пропуска verify.
- **Человеку:** таблица «улика → пропущенный скилл → что открыть следующим сообщением».

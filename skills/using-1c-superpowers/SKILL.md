# Роутер 1c-superpowers

Открывай этот скилл **до ответа** на любую задачу по 1С. Сначала выбери процессный скилл и открой его; только потом пиши код, diff или совет.

Скиллы лежат рядом в одном каталоге (`skills/`) и ссылаются друг на друга по относительным путям. Скрипт `find_checks.py` живёт в `1c-verification/scripts/`. Учебные сценарии и evals лежат в репозитории плагина (`scenarios/`, `evals/`), для работы скиллов они не нужны.

## Приоритет

1. **Процессные скиллы** — brainstorming, план, TDD, отладка, verify, review, finish.
2. **MCP и инструменты** — после выбора процесса, не вместо него.
3. Не отвечать «из головы» по доработке, проведению, обмену или сдаче без открытого скилла.

Перед сдачей или «можно мержить» — обязательно `1c-verification`; пропуск verify запрещён.

Если сомневаешься в маршруте — `1c-brainstorming` для новой фичи или `1c-review`, если уже есть diff и просьба проверить.

## Фраза → скилл

Полный список примеров фраз: `scenarios/routing-phrases.md` в репозитории плагина.

| Фраза / намерение | Скилл |
|---|---|
| новая обработка, «сделай», неясные требования | `1c-brainstorming` |
| разложи на задачи, план работ | `1c-writing-plans` |
| по плану давай код, выполни план | `1c-executing-plans` |
| сначала тест, TDD | `1c-tdd` |
| не проводится, ЖР, ошибка в рантайме | `1c-systematic-debugging` |
| тормозит, долго проводится, таймаут блокировки, deadlock | `1c-performance` |
| проверено, можно сдавать, готово к MR | `1c-verification` |
| ревью MR, diff, «проверь код» | `1c-review` |
| замечания с ревью, правки по review | `1c-receiving-review` |
| закрой ветку, MR готов к merge | `1c-finish-branch` |
| расширение, &Вместо, CFE | `1c-extension` |
| обновление поставщика, сравнение релизов | `1c-update` |
| HTTP, пакет обмена, интеграция | `1c-exchange` |
| новый скилл, правило для агента | `1c-writing-skills` |
| скиллы не срабатывают, роутер сломан | `diagnosing-1c-superpowers` |

## Словарь

| Термин | Значение |
|---|---|
| Шлагбаум | проверка перед сдачей: `1c-verification` и `gate.md` |
| Эталон проверки (в скиллах «оракул») | тест, сценарий или ожидаемый вход → результат, с которым сверяют поведение |
| Bake | прогон скилла на учебной фикстуре с зафиксированным ожиданием |
| Юрисдикция diff | судить только изменённые и явно подтянутые файлы |
| Четыре класса | нарушение, законный случай, не хватает факта, отдать человеку |

# Шлагбаум проверки

Слово «проверено», «готово», «замечаний нет» требует свежего доказательства в этом же ответе. Доказательство, добытое раньше по ходу разговора, не считается. Человеку показывается сводка из этого набора, не карточка на каждое правило.

## Что считается доказательством

Нарушение закрыто, только если в ответе есть класс «нарушение», модуль и цитата строки либо вывод поиска по выгрузке.

«Замечаний нет» допустимо, если в резюме есть строка, какие контуры смотрелись, и по ним нет нарушения. Каждое правило отдельной карточкой не классифицировать. Контур, который есть в изменённом коде и в резюме не назван, молчанием не закрывается.

Режим совместимости и версия БСП (из выгрузки или от автора, см. [facts.md](facts.md)) нужны **только если** совпавшая карточка зависит от версии: `versions.md`, `Асинх`, номер БСП, блокировки по режиму. Тогда без них по этой теме — «не хватает факта» и слово «проверено» по ней не писать. Если в diff таких карточек нет, отсутствие этих данных проверку не блокирует.

Область слова «проверено» всегда назвать: «проверено в пределах присланного diff: контуры X, Y; версия и БСП не читались». Такая формулировка допустима без выгрузки. Голое «проверено» без области — нет. Версию установленной платформы из режима совместимости не собирать. Подробности — в [versions.md](versions.md).

Синтаксический прогон, анализатор BSL и сценарии — второй контур. Зелёный лог не снимает критичное замечание по проведению, правам, двойной записи и обмену.

## Что запускать

Сначала `python3 <каталог скилла 1c-verification>/scripts/find_checks.py <корень репозитория>`. Скрипт только смотрит файлы. Метка «можно читать файлы» у `Configuration.xml` значит «есть что читать», а не «есть команда проверки».

Дальше:

- В списке есть проверка с меткой «можно читать файлы». Запустить её, если команда есть в системе, и привести хвост лога и код возврата. Нет команды в системе — написать «проверка объявлена, запуска нет», не «синтаксис чист».
- В списке метка «не запускать из ревью». Это загрузка конфигурации, обновление базы, предприятие, Vanessa, которая ходит в базу. Не запускать. В ответе перечислить, что увидено и почему оставлено.
- Список пуст. Фраза «шлагбаум не настроен». Это не дефект кода и не повод ставить в репозиторий Vanessa.

## Рецепты команд (сверять с README и CI проекта)

- **BSL Language Server** (файлы, базу не трогает, нужна Java): `bsl-language-server --analyze --srcDir <каталог выгрузки> --reporter junit` пишет `bsl-junit.xml` в текущий каталог; на большой выгрузке добавить `-Xmx4g` для Java. Можно запускать, если в `find_checks` есть `.bsl-language-server.json` или CI уже его гоняет. Хвост лога и код возврата привести в ответе.
- **YAxUnit** запускает **Предприятие на базе**: `1cv8c ENTERPRISE /IBName <база> /N <пользователь> /C RunUnitTests=<путь к yaxunit.json>`. Из ревью не запускать. Для `1c-tdd` только командой проекта; расширение YAxUnit в базе должно быть без безопасного режима и защиты от опасных действий.
- Команды, которой в README или CI нет, не придумывать: «проверка объявлена, запуска нет».

## Что не делать

Не грузить конфигурацию в базу. Не выполнять BSL на базе. Не открывать файл `1CD`. Не считать прошедший `find_checks.py` прогоном тестов: он ничего не проверяет в коде, только показывает, какой шлагбаум есть.

Нет выгрузки и нет присланного модуля — ревью не завершать фразой «замечаний нет». Класс «не хватает факта». Есть присланный модуль без выгрузки — ревью возможно в пределах фрагмента, область назвать.

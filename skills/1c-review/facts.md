# Источники фактов о конфигурации

Плагин **не поставляет свой MCP**. Факты о конфигурации берутся из того, что есть: файлы выгрузки в репозитории, слова автора или любой готовый MCP метаданных. Названия инструментов у серверов разные, поэтому скиллы говорят о **фактах**, а не об именах вызовов.

## Какие факты нужны и откуда их взять

| Факт | Файлы выгрузки | Готовый MCP (если подключён) |
|---|---|---|
| Режим совместимости | `Configuration.xml`, `CompatibilityMode` | метаданные конфигурации |
| Режим управления блокировками | `Configuration.xml`, `DataLockControlMode` | метаданные конфигурации |
| Релиз платформы | в выгрузке его нет: слова автора, окно «О программе» | справка по платформе, если сервер её даёт |
| Версия БСП | модуль регистрации подсистемы в выгрузке (`СтандартныеПодсистемы`); регистр версий в файлах не лежит | поиск по коду |
| Флаги общего модуля (клиент, сервер, вызов сервера, повторное использование, привилегированный) | XML общего модуля | карточка объекта |
| Реквизиты, табличные части, свойства проведения, роли | XML объекта | карточка объекта |
| Текст процедуры и её вызовы | `.bsl` в выгрузке | чтение модуля, поиск по коду |
| Сигнатура и граница версии метода платформы | нет | синтаксис-помощник платформы |

Фактов нет ни в файлах, ни у MCP — класс «не хватает факта», не додумывать.

## Готовые MCP для 1С (не наши)

Подключать на свой выбор, перед использованием читать их README: состав инструментов и требования у каждого свои. Сводный список: [Untru/1c-mcp](https://github.com/Untru/1c-mcp).

**Проверено запуском (2026-10-02, на тестовой выгрузке): [feenlace/mcp-1c](https://github.com/feenlace/mcp-1c) v1.22.2.** Запускается как stdio-сервер с `--dump <каталог DumpConfigToFiles>`, отдаёт 11 инструментов. Без запущенной базы 1С реально работают только:
- `search_code`: полнотекстовый поиск по модулям выгрузки (первые секунды после старта индекс строится, нужен повтор);
- `bsl_syntax_help`: справка по встроенным функциям BSL.

Инструменты `get_configuration_info`, `get_object_structure`, `get_metadata_tree`, `get_form_structure`, `analyze_subsystems` ходят в HTTP-сервис расширения внутри **запущенной базы** и в режиме `--dump` без неё возвращают ошибку соединения. `execute_query` и `get_event_log` читают данные и журнал базы, их из ревью не вызывать.

Остальные серверы нами не запускались, сведения из их README:
- Метаданные и структура из файловой выгрузки: [Vovchik45/mcp-1c](https://github.com/Vovchik45/mcp-1c) (Python, Apache-2.0: объекты, процедуры, вызовы, синтаксис, расширения), [shultzMAN87/mcp_for-1C](https://github.com/shultzMAN87/mcp_for-1C) (граф метаданных и вызовов; нужен Docker).
- Внутри EDT: [Desko77/ai-edt](https://github.com/Desko77/ai-edt), [SeKam68/edt-companion-mcp](https://github.com/SeKam68/edt-companion-mcp), [fedukhin-sys/1C_EDT_MCP_PUBLIC](https://github.com/fedukhin-sys/1C_EDT_MCP_PUBLIC).
- BSL Language Server: [SteelMorgan/mcp-bsl-lsp-bridge](https://github.com/SteelMorgan/mcp-bsl-lsp-bridge), [Vladimirov-Maxim/bsl-ls-mcp](https://github.com/Vladimirov-Maxim/bsl-ls-mcp), [phsin/mcp-bsl-ls](https://github.com/phsin/mcp-bsl-ls).
- Запуск тестов YAxUnit: [alkoleft/mcp-onec-test-runner](https://github.com/alkoleft/mcp-onec-test-runner) (обновляет базу и гоняет тесты на ней, из ревью не использовать).
- Метаданные через HTTP-сервис расширения в базе: [artesk/1C_MCP_metadata](https://github.com/artesk/1C_MCP_metadata) (только на разработческой копии, не на рабочей).

**Практический вывод.** Режим совместимости, режим блокировок, флаги общего модуля и состав объекта лежат в XML выгрузки обычными свойствами: агент читает их напрямую (поиск и чтение файлов), MCP для этого не обязателен. MCP нужен для удобного поиска по коду, справки по платформе и, если подключена разработческая база, для структуры объектов.

## Границы, которые не зависят от выбранного MCP

- Только чтение. Инструменты, которые меняют конфигурацию, обновляют или загружают в базу, запускают клиент, отлаживают или читают журнал рабочей базы, из ревью и `1c-verification` не вызывать.
- Рабочую базу не открывать, файл `1CD` не читать.
- Ответ MCP — тоже факт «из присланного»: имени объекта, которого он не вернул, в замечании нет.

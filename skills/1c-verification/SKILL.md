# Проверка перед сдачей

Предмет — diff и то, что автор явно приложил к задаче. Четыре класса там, где есть суждение: **нарушение**, **законный случай**, **не хватает факта**, **отдать человеку**. Юрисдикция diff: объекта или контура нет среди изменённых и подтянутых файлов — замечание не открывать.

## Когда открывать

- Автор или агент собирается написать «проверено», «готово», «замечаний нет», «можно мержить», «CI зелёный».
- Перед финальной сдачей расширения или MR, когда синтаксис уже прогнан, но смысл diff ещё не закрыт.
- Роутер `using-1c-superpowers` направил сюда после фраз про сдачу.

Не подменяет полное ревью diff: замечания по проведению, правам и обмену классифицируются здесь только как факты для шлагбаума; итоговая сводка — у `1c-review`.

## Шаги по порядку

1. **Область.** Какие файлы и контуры реально в diff: проведение, обмен, расширение, запрос. Вне diff — не додумывать.
2. **Свежие факты.** В этом же ответе: что запускали и что увидели. Доказательство из прошлых сообщений не переносить.
3. **Шлагбаум.** Чеклист и правила доказательства — [../1c-review/gate.md](../1c-review/gate.md). Данные конфигурации (режим совместимости, БСП) нужен только для тем, зависящих от версии; для остального «проверено» допустимо в названной области присланного diff. Версионная тема без этих данных — «не хватает факта» по ней.
4. **Команды.** `python3 scripts/find_checks.py <корень>` из каталога этого скилла (`1c-verification`); дальше только то, что скрипт разрешил. Зелёный синтаксис не снимает критичное по проведению, правам, двойной записи и обмену.
5. **Передача.** Кратко: какие контуры смотрелись, что доказано, где дыра факта; указать HEAD (`git rev-parse --short HEAD`), если это репозиторий. Затем один раз открыть `1c-review` для сводки и вердикта (править / сдать с оговоркой / можно сдавать).

## Красные флаги

| Мысль | Что делать |
|---|---|
| «BSL LS зелёный, значит проверено» | Синтаксис — второй контур |
| «Проверял в прошлом сообщении» | Свежее доказательство в этом ответе |
| «Нет данных конфигурации, значит ничего нельзя сказать» | Можно, в названной области присланного diff, без версионных тем |

## Стоп и запреты

- Не писать «проверено» или «можно сдавать» без свежего доказательства в этом ответе.
- Не считать зелёный BSL LS или сценарий синтаксиса достаточным для сдачи.
- Не грузить конфигурацию в базу, не выполнять BSL на базе, не открывать `1CD`, не запускать проверки с меткой «не запускать из ревью» из [gate.md](../1c-review/gate.md).
- Не писать сводку и вердикт сдачи — это только `1c-review`.
- Нет выгрузки и нет присланного модуля — не завершать фразой «замечаний нет»; класс «не хватает факта».

## Что отдать review и человеку

- **1c-review:** список контуров, результаты `find_checks` и разрешённых прогонов, классы по каждому найденному риску, явные «не хватает факта» и «отдать человеку».
- **Человеку:** что ещё нужно приложить (вторая выгрузка CFE, режим совместимости и БСП, фрагмент проведения), если без этого шлагбаум не закрывается.

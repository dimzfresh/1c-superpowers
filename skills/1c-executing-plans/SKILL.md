# Исполнение плана (executing-plans)

Предмет — текст плана из `1c-writing-plans` (чат или `docs/superpowers/plans/`). Правки — только в путях и объектах текущей задачи плана.

## Когда открывать

- Есть утверждённый план; пользователь просит «по плану», «давай код», «выполни задачу N».
- Роутер направил после `1c-writing-plans`.

Не открывать без плана — сначала `1c-brainstorming` / `1c-writing-plans`.

## Шаги по порядку

1. **Загрузить план.** Прочитать задачи, **пути** XML/BSL, проверки и риски CFE; расхождения с репо — остановиться и уточнить.
2. **Одна задача за раз.** Шаг исполнения = **одна задача плана**; не смешивать соседние; не добавлять «заодно» рефакторинг вне плана.
3. **Правки.** Минимальный diff под задачу; расширение, `&Вместо`, основная конфигурация — по карточкам [../1c-review/extension.md](../1c-review/extension.md).
4. **Проверка задачи.** То, что указано в плане для этой задачи; `find_checks.py` из каталога скилла `1c-verification` (`scripts/find_checks.py <корень проекта>`), если применимо.
5. **Сбой.** Падение теста, проведение, ЖР, неясная инструкция — **стоп**, открыть `1c-systematic-debugging`; не угадывать и не расширять scope «починкой сбоку».
6. **Финиш плана.** Все задачи закрыты → `1c-verification` (свежие факты в этом ответе) → `1c-review` для сводки и вердикта. Слова «проверено» / «можно сдавать» — только после этой цепочки.

## Красные флаги

| Мысль | Что делать |
|---|---|
| «Заодно поправлю соседний модуль» | Вне задачи плана — нет, вернуться в `1c-writing-plans` |
| «Тест упал, попробую быстрый фикс» | Стоп, `1c-systematic-debugging` |
| «Все задачи сделал, значит готово» | Сначала `1c-verification` |

## Стоп и запреты

- Не расширять scope за пределами плана без возврата к `1c-writing-plans` и согласия пользователя.
- Не писать сводку и вердикт сдачи — только `1c-review`.
- Не пропускать verify перед заявлением о готовности к MR.
- Нет второй выгрузки CFE — не утверждать цепочку перехватов; **не хватает факта**.

## Что отдать review и человеку

- **1c-verification / 1c-review:** какие задачи плана выполнены, какие **пути** менялись, результаты проверок, открытые «не хватает факта».
- **Человеку:** статус по задачам плана; при блокере — один чёткий запрос факта или переход в отладку.

# Написание скиллов и карточек

Предмет — новый процессный SKILL.md или карточка правила в каталоге `1c-review/`. Единственный канон карточек — файлы [../1c-review/](../1c-review/); процессные скиллы ссылаются на них, не дублируют таблицы.

## Когда открывать

- «Новый скилл», «правило для агента», «добавь карточку в review».
- Роутер направил по фразам про skill или карточку.

## Формат карточки (обязательно)

Каждое правило — заголовок `###` и ровно четыре метки:

- **Когда ставить:** условие срабатывания в diff или в явном факте автора.
- **Не ставить:** законные случаи и «не хватает факта» — **исключения обязательны**, без пустого «Не ставить».
- **Как доказать:** что процитировать из diff или выгрузки.
- **Тяжесть:** критично | важно | мелочь (для review — см. gate).

Правило без исключения в «Не ставить» не публиковать. Без дублирования сводки review в SKILL соседнего процесса.

## Формат процессного SKILL.md

- YAML: `name`, `description` — триггеры, без фразы «пишет сводку» (сводку пишет только `1c-review`).
- Тело: когда открывать, шаги, стоп, передача в `1c-review`.
- Карточки новых нарушений — в `1c-review/*.md`, не только в SKILL.

## Проверка перед merge

0. **Сначала провал без правила.** Добавить кейс в `evals/negative.json` (фикстура + regex) и прогнать `evals/run_eval.py` без набора и с ним: правило оправдано, только если без него ответ ошибается, а с ним нет. Исключение из «Не ставить» подтверждать кейсом законного приёма.

1. `python3 -m unittest discover -s tests -v` из корня плагина — все тесты зелёные.
2. `test_every_rule_has_an_exception` — у каждого `###` в `.md` четыре метки.
3. `test_one_summary_door` — только `1c-review` владеет сводкой.

## Стоп и запреты

- Не публиковать карточку без блока «Не ставить» с хотя бы одним исключением или «не хватает факта».
- Не класть вердикт «можно сдавать» в description соседнего скилла.
- Не писать сводку diff — открыть `1c-review` после добавления правила.

## Что отдать review и человеку

- **1c-review:** если новое правило меняет вердикт типового diff — один прогон на fixture или примере из сценария.
- **Человеку:** путь к новому файлу, имя скилла для [using-1c-superpowers](../using-1c-superpowers/SKILL.md) и `scenarios/routing-phrases.md` репозитория плагина.

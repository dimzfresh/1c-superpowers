# Сценарий bake: HTTP в проведении (калибровка 1c-review)

**Фикстура для ручного bake.** Модуль объекта документа (без diff, целиком как присланный фрагмент):

`tests/fixture-http-posting/Documents/ЗаказКлиента/Ext/ObjectModule.bsl`

В `ОбработкаПроведения`: запрос с одним `Выполнить()` до цикла по выгрузке; в теле цикла создаётся второй `Запрос` без вызова `Выполнить`; затем `HTTPСоединение = Новый HTTPСоединение("shop.example")` и реальный вызов `HTTPСоединение.Получить(...)`.

**Вход bake.** Открыты `using-1c-superpowers` и `1c-review`. Просьба: «проверь модуль / ревью проведения» по фикстуре выше. Слов «проверено», зелёного CI и данных конфигурации нет — только код.

**Юрисдикция.** Только присланный фрагмент `ОбработкаПроведения`. Регистры обмена, транзакции `НачатьТранзакцию` и движения в diff не выдумывать; HTTP в теле проведения виден напрямую.

**Ожидание (калибровка review).**

- Класс **нарушение** по [exchange.md](../skills/1c-review/exchange.md) («Внешний вызов и транзакция» / HTTP в проведении), тяжесть **критично**.
- **Вердикт:** **править** (блокирующее для сдачи).
- В замечании — **HTTP** или **соединение** в контексте **проведения** (`ОбработкаПроведения`), не общий совет «избегайте сети» без привязки к процедуре.
- Не подтверждать **«проверено»**, **«можно сдавать»** и не ставить вердикт «можно сдавать» только потому, что синтаксис читается.
- Хост **`shop.example`** — учебный placeholder, не секрет: замечание по [secrets.md](../skills/1c-review/secrets.md) **не** ставить.
- **Ложное «запрос в цикле»** не ставить: единственный `Выполнить()` — в выражении коллекции `Для Каждого … Из Запрос.Выполнить().Выгрузить()`, не в теле итерации; второй `Запрос` в цикле без `Выполнить` — не «запрос в цикле» по [queries.md](../skills/1c-review/queries.md) и блоку ложных запретов в SKILL.

**Сводку и вердикт** пишет только **1c-review**; `1c-exchange` и `1c-verification` классифицируют факты и шлагбаум, но не подменяют итог bake.

# Сценарий: merge vendor с «убийцами» в diff

**Вход.** Автор сливает ветку обновления поставщика в свою. В diff: `&Вместо` на проведении без продолжения; правка общего модуля БСП в каталоге основной конфигурации; в CFE добавлена роль `ПолныеПрава`; в модуле проведения — HTTP-вызов внутри транзакции. Новая выгрузка поставщика приложена только для основной, CFE одна.

**Юрисдикция diff.** Смотреть только присланные файлы и явные выгрузки; платформу и номер БСП не выдумывать.

**Ожидание (1c-update → 1c-review).**

- Чеклист «убьёт merge»: каждый из четырёх пунктов классифицирован с цитатой (**нарушение** или **не хватает факта** по сигнатуре, если нет сравнения с новым vendor).
- **&Вместо** без продолжения на проведении — **нарушение**, не закрывать молчанием.
- **Правка модуля БСП в основной** — **нарушение** (обновление затрёт).
- **ПолныеПрава в CFE** — по standards: **нарушение**, если нет доказанной нужды в diff.
- **HTTP в проведении** — **нарушение** по контуру обмена/транзакции.
- Слово «merge безопасен» не писать до review.
- Сводку и вердикт (**править** / сдать с оговоркой) формирует только **1c-review**.

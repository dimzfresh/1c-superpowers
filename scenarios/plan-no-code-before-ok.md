# Сценарий: план и код только после «ок»

**Вход.** Пользователь: «сделай обработку выгрузки в XML». Требования размыты, diff ещё нет.

**Юрисдикция.** До явного согласия на дизайн — **без кода** и без правок BSL/XML в репозитории. Границы diff, CFE и «не хватает факта» — на этапе brainstorming.

**Ожидание (1c-brainstorming → 1c-writing-plans → 1c-executing-plans).**

- **1c-brainstorming:** один вопрос за раз; секции дизайна; после «ок» — переход к плану, не к модулю.
- **1c-writing-plans:** задачи по 2–5 минут; у каждой — **пути** к файлам выгрузки (`.xml`, `.bsl`), проверка, риск обновления/CFE.
- **1c-executing-plans:** шаг = задача плана; scope не расширять; сбой → `1c-systematic-debugging`; перед сдачей → `1c-verification` и `1c-review`.

# Что добавляют факты о конфигурации (выгрузка или MCP), 2026-10-02

Режимы: `skills_*` — с текстом скиллов, `base_*` — без; `*_facts` — в промпт добавлены данные конфигурации (как их вернул бы любой MCP метаданных или чтение `Configuration.xml`), `*_nofacts` — только код. 6 кейсов, в которых правильный ответ зависит от факта: режим блокировок (Managed / Automatic), флаг повторного использования модуля (DuringSession / DontUse), релиз платформы для `Асинх` (8.3.12 / 8.3.22). Сырые ответы: `<id>.<mode>.<n>.txt`; оценка `python3 evals/run_facts_eval.py --check`, вердикты `--verdicts`.

## Главный результат: вердикт со скиллами меняется от фактов так, как задумано

| Кейс (код один и тот же) | skills, без фактов | skills, с фактами |
|---|---|---|
| lock-managed (Блокировки: Managed) | «сдать с оговоркой» + «не хватает факта» (3/3) | **«править»** (3/3) |
| lock-auto (Блокировки: Automatic) | «сдать с оговоркой» + «не хватает факта» (3/3) | **«можно сдавать»** (3/3), блокировку не требует |
| cache-session (DuringSession, структура параметром) | «сдать с оговоркой» + «не хватает факта» (3/3) | «сдать с оговоркой»: нарушение «важно» подтверждено |
| cache-off (DontUse) | «сдать с оговоркой» + «не хватает факта» (3/3) | **«можно сдавать»** (3/3) |
| async-old (платформа 8.3.12) | «сдать с оговоркой» + «не хватает факта» (3/3) | «сдать с оговоркой»: `Асинх` недоступен, нарушение |
| async-new (платформа 8.3.22) | «сдать с оговоркой» + «не хватает факта» (3/3) | **«можно сдавать»** (3/3) |

Без фактов набор ни разу не выдаёт уверенный вердикт («править» или «можно сдавать») по версионным и конфигурационным темам: всегда оговорка и явный пробел. С фактами вердикт становится определённым и верным по каждому кейсу. Это и есть вклад MCP или выгрузки: он превращает «не хватает факта» в точный ответ, в том числе «можно сдавать» там, где без фактов нельзя.

## Вторичные результаты
- Критерии по regex (`--check`): skills_facts 18/18, skills_nofacts 17/18, base_facts 17/18. Различие незначительное; один провал `base_facts` (lock-auto): модель при Automatic всё равно советовала `БлокировкаДанных`. Со скиллами и фактами этого не было ни разу (3/3).
- Модель без скиллов не использует формат вердикта, поэтому сравнить «вердикты» с базой нельзя, только содержание ответов.

## Ограничения
- Ячейка `base_nofacts` почти пустая (1 ответ из 18): три агента этого режима остановил защитный классификатор модели (ложное срабатывание), повторно эти прогоны я не перефразировала и не обходила. Сравнение «база без фактов» по этому eval не делалось.
- 6 кейсов, n=3, одна модель, факты подставлены в промпт вручную, а не получены вызовом реального MCP. Реальные серверы (список в `skills/1c-review/facts.md`) нами не запускались.

## Проверка реального сервера: feenlace/mcp-1c v1.22.2 (2026-10-02)
Скачан бинарник `mcp-1c-darwin-arm64` (15,1 МБ) с GitHub Releases, сумма сверена с `checksums.txt`, запуск локально по stdio с `--dump` на тестовой выгрузке, база не использовалась. Результат: без запущенной базы 1С работают `search_code` (нашёл `HTTPСоединение` в модуле документа с номером строки) и `bsl_syntax_help`. Инструменты конфигурации и структуры объектов обращаются к HTTP-сервису в базе и без неё падают с ошибкой соединения. Значит, в нашем eval «с фактами» подставлялись данные, которые этот сервер без базы отдать не может (режим блокировок, флаги модуля); их агент берёт из XML выгрузки напрямую. Eval с реальными ответами сервера не гонялся.

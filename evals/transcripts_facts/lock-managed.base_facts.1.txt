Ревью ОбработкаПроведения (конфигурация «Склад», совместимость Version8_3_24, режим блокировок: Managed)

Главная проблема: нет управляемой блокировки перед проверкой остатка (критично).

Режим блокировок конфигурации Managed. Платформа сама не защитит чтение остатков от параллельных проведений, это нужно делать вручную через БлокировкаДанных. Сейчас запрос читает остаток без блокировки, затем документ пишет расход. Два документа, проводимых одновременно по одной номенклатуре и складу, оба прочитают один и тот же остаток, оба пройдут проверку «Остаток < Количество» и оба спишут товар. В итоге остаток уйдет в минус, то есть возникнет перепродажа. Проверку остатка и запись движений надо выполнять под исключительной блокировкой регистра по измерениям.

Исправление: поставить блокировку до запроса. Проведение уже выполняется в транзакции, блокировка снимется при ее завершении.

```bsl
Процедура ОбработкаПроведения(Отказ, РежимПроведения)

	Блокировка = Новый БлокировкаДанных;
	ЭлементБлокировки = Блокировка.Добавить("РегистрНакопления.СвободныеОстатки");
	ЭлементБлокировки.Режим = РежимБлокировкиДанных.Исключительный;
	ЭлементБлокировки.УстановитьЗначение("Номенклатура", Номенклатура);
	ЭлементБлокировки.УстановитьЗначение("Склад", Склад);
	Блокировка.Заблокировать();

	Запрос = Новый Запрос;
	Запрос.Текст = "ВЫБРАТЬ Остатки.КоличествоОстаток КАК Остаток ИЗ РегистрНакопления.СвободныеОстатки.Остатки(, Номенклатура = &Номенклатура И Склад = &Склад) КАК Остатки";
	Запрос.УстановитьПараметр("Номенклатура", Номенклатура);
	Запрос.УстановитьПараметр("Склад", Склад);
	Выборка = Запрос.Выполнить().Выбрать();
	Остаток = ?(Выборка.Следующий(), Выборка.Остаток, 0);

	Если Остаток < Количество Тогда
		Сообщение = Новый СообщениеПользователю;
		Сообщение.Текст = "Недостаточно товара на складе: доступно " + Остаток + ", требуется " + Количество;
		Сообщение.УстановитьДанные(ЭтотОбъект);
		Сообщение.Сообщить();
		Отказ = Истина;
		Возврат;
	КонецЕсли;

	Движения.СвободныеОстатки.Записывать = Истина;
	Движение = Движения.СвободныеОстатки.ДобавитьРасход();
	Движение.Период = Дата;
	Движение.Номенклатура = Номенклатура;
	Движение.Склад = Склад;
	Движение.Количество = Количество;

КонецПроцедуры
```

Важно: блокировку нужно ставить до чтения остатков. Если поставить ее после запроса, ошибка останется.

Замечания поменьше:

1. При Отказ = Истина пользователь не получает объяснения. Нужно выдавать сообщение (в примере выше оно есть).
2. Остатки запрашиваются на текущий момент без указания момента времени. Для документа, который может проводиться задним числом, остаток надо брать на момент документа (например, через МоментВремени()), иначе проверка будет некорректной. Если у вас оперативное проведение только по текущей дате, это допустимо, но стоит проверить.
3. Альтернативный подход: сначала записать движения, затем проверить отрицательные остатки запросом по таблице остатков (контроль после записи). Он требует той же исключительной блокировки или управляемой блокировки с контролем остатков, поэтому выигрыша по защите от гонок не дает.

Итог: код корректен по логике, но в Managed-режиме без блокировки данных он небезопасен при параллельной работе. Добавьте исключительную блокировку по Номенклатура и Склад перед запросом.

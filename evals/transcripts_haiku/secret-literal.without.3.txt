Найдена критическая проблема безопасности:

**Проблема:** В коде на сервере хардкодирован пароль в виде текстового литерала:
```
Пароль = "УЧЕБНЫЙ_ЛИТЕРАЛ_ПАРОЛЯ";
HTTPСоединение = Новый HTTPСоединение("api.example.com", , "svc", Пароль);
```

**Риск:**
- Учетные данные будут видны в исходном коде и в истории версий
- Любой разработчик, имеющий доступ к репозиторию, получит доступ к пароліщу
- Пароль будет скомпилирован в конфигурацию
- Сложно ротировать учетные данные

**Рекомендация:**
1. Немедленно изменить пароль на сервере 1С и в системе api.example.com
2. Использовать защищенное хранилище учетных данных вместо хардкода:
   - Параметры конфигурации (Константы)
   - Переменные окружения (для облачных решений)
   - Защищенные параметры сеанса
   - Встроенное хранилище паролей 1С (если доступно)

Пример исправления:
```
Пароль = Константы.ПарольАПИ.Получить();
HTTPСоединение = Новый HTTPСоединение("api.example.com", , "svc", Пароль);
```

3. Удалить исходный пароль из истории git (использовать git filter-branch или переписать историю)
4. Добавить правило в .gitignore для файлов с конфиденциальной информацией

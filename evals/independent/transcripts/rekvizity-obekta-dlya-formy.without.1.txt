Посмотрел. В таком виде функцию выкладывать нельзя, это дыра по безопасности. Идея (один серверный вызов вместо нескольких обращений к реквизитам) нормальная, но реализация небезопасна.

1. Привилегированный режим на экспортной функции с вызовом сервера (критично).
УстановитьПривилегированныйРежим(Истина) отключает проверку прав и RLS. Функция вызывается с клиента для любой ссылки, поэтому любой пользователь, который может вызвать серверный вызов, получает значения любых реквизитов любого объекта, включая те, к которым у него нет доступа (зарплата, закупочные цены, персональные данные и т.д.). Привилегированный режим тут убирать полностью, чтобы запрос выполнялся с правами текущего пользователя и ограничениями на уровне записей. Если кому-то нужен доступ в обход прав, это отдельная функция с явной проверкой и обоснованием.

2. Инъекция в текст запроса (критично).
ИменаРеквизитов подставляются в текст запроса через СтрШаблон без проверки. С клиента можно передать что угодно, например список реквизитов с вложенным подзапросом или обращением к другим таблицам через точку (Ссылка.Владелец.Пароль...), а в связке с привилегированным режимом это чтение произвольных данных. Нужно:
- принимать имена как массив или строку, разбирать их и проверять каждое имя по метаданным объекта (Метаданные.Реквизиты, СтандартныеРеквизиты, при необходимости общие реквизиты);
- разрешать только простые имена (идентификаторы), без точек, скобок, запятых внутри имени;
- в запрос подставлять только проверенные имена, собираемые самой функцией.

3. Проверка прав на конкретные реквизиты.
Даже без привилегированного режима запрос с "Т.Реквизит" выдаст ошибку, если нет права на чтение. Лучше заранее проверять доступ к объекту и реквизиту и возвращать понятную ошибку, а не падение запроса. Ещё лучше воспользоваться готовыми средствами типовой библиотеки (в БСП это ОбщегоНазначения.ЗначенияРеквизитовОбъекта(Ссылка, ИменаРеквизитов)). Она делает именно это: проверяет имена реквизитов и работает с правами пользователя. Проверьте, не дублируем ли мы существующую функцию. Если ограничения БСП не подходят, нужно обосновать, чем именно.

4. Некорректные входные данные.
- Пустая ссылка: Метаданные() вернёт объект, запрос вернёт пусто, на выходе пустая структура, и вызывающий код не отличит это от ошибки. Нужно либо проверять ЗначениеЗаполнено(Ссылка), либо возвращать структуру с пустыми значениями.
- Не ссылочный тип передали: Ссылка.Метаданные() упадёт с неочевидной ошибкой, проверьте ОбщегоНазначения.ЭтоСсылка(ТипЗнч(Ссылка)).
- Пустая строка реквизитов: запрос получится невалидным.
- Табличные части и "Т.Ссылка.Реквизит" через точку: решить явно, поддерживаем или нет.

5. Недостатки реализации.
- ИмяТаблицы получается через Метаданные().ПолноеИмя(), это годится для справочников и документов, но не для всех типов объектов (например, перечисления); ограничьте допустимые типы.
- Результат строится по колонкам результата запроса, имена колонок совпадают с именами реквизитов, это нормально. Но если в строке реквизитов был псевдоним ("КАК"), структура получит другие ключи. Лучше формировать запрос самим из массива имён, без пользовательских псевдонимов.
- Для маленьких наборов реквизитов запрос тяжелее, чем ОбщегоНазначения.ЗначенияРеквизитовОбъекта, которая умеет ещё и кэшировать.

6. Рекомендация.
Либо заменить вызовом ОбщегоНазначения.ЗначенияРеквизитовОбъекта, либо переписать так:

```bsl
Функция ДанныеОбъектаДляФормы(Ссылка, ИменаРеквизитов) Экспорт

	Если Не ОбщегоНазначения.ЭтоСсылка(ТипЗнч(Ссылка)) Тогда
		ВызватьИсключение НСтр("ru = 'Параметр Ссылка должен быть ссылкой.'");
	КонецЕсли;

	МетаданныеОбъекта = Ссылка.Метаданные();
	Результат = Новый Структура;
	МассивИмен = СтрРазделить(ИменаРеквизитов, ",", Ложь);

	ПоляЗапроса = Новый Массив;
	Для Каждого Имя Из МассивИмен Цикл
		Имя = СокрЛП(Имя);
		// Только имена реквизитов самого объекта и стандартные реквизиты
		Если МетаданныеОбъекта.Реквизиты.Найти(Имя) = Неопределено
			И МетаданныеОбъекта.СтандартныеРеквизиты.Найти(Имя) = Неопределено Тогда
			ВызватьИсключение СтрШаблон(НСтр("ru = 'Реквизит %1 не найден в %2'"), Имя, МетаданныеОбъекта.ПолноеИмя());
		КонецЕсли;
		ПоляЗапроса.Добавить("Т." + Имя + " КАК " + Имя);
	КонецЦикла;

	// ... дальше запрос без привилегированного режима, под правами пользователя

КонецФункции
```

Итого: привилегированный режим убрать, имена реквизитов валидировать по метаданным (или использовать готовую функцию из БСП), входные данные проверять. До этого в продуктив не выкладывать.

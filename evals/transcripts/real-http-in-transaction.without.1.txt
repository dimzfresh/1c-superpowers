Ревью процедуры ПринятьЗаказ

Критично: HTTP-вызов внутри открытой транзакции (строки 6-11).

Соединение.Получить(...) выполняет реальный сетевой запрос между НачатьТранзакцию() и ЗафиксироватьТранзакцию(). Пока внешний сервис отвечает, транзакция открыта, а блокировки на записанный Заказ (и связанные данные, регистры) удерживаются. Последствия:
- другие сеансы ждут блокировки на время сетевого ожидания, возможны таймауты и взаимоблокировки;
- при медленном или недоступном сервисе транзакция висит до таймаута;
- если запрос упал, откатывается и запись заказа, хотя это внешняя проверка статуса. Если запрос прошёл, а фиксация упала, внешний мир уже получил обращение. Откатить сетевой вызов нельзя.

Как исправить: выполнить HTTP-запрос вне транзакции. Либо до записи (если статус нужен для решения), либо после ЗафиксироватьТранзакцию(). Если нужна гарантированная доставка, записывать намерение в регистр или очередь внутри транзакции, а отправку делать фоновым заданием.

Прочие замечания:
1. Результат Ответ не используется. Статус ответа (КодСостояния) не проверяется, поэтому ошибка сервиса молча игнорируется.
2. У HTTPСоединения не задан таймаут. Установите его, чтобы вызов не висел бесконечно.
3. Соединение без защищённого протокола (нет параметров SSL). Для боевого API нужен HTTPS.
4. Номер для запроса склеивается в строку без экранирования: "/status/" + Заказ.ВнешнийНомер. Если номер может содержать спецсимволы, кодируйте его.

Итог: в текущем виде не сдавать, пункт про HTTP в транзакции обязателен к исправлению.

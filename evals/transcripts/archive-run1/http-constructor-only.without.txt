## Ревью процедуры ОбработкаПроведения

### Критичные замечания

1. **HTTPСоединение создаётся, но не используется.**
   `Новый HTTPСоединение("api.shop.example")` только создаёт объект соединения. Сам запрос не отправляется: нет `HTTPЗапрос` и нет вызова `Получить`, `Записать` или `ОтправитьДляОбработки`. Переменная нигде не используется, поэтому строка бессмысленна. Если в задумке был вызов внешнего API, его нужно либо реализовать, либо удалить строку.

2. **Внешний HTTP-вызов в транзакции проведения.**
   `ОбработкаПроведения` выполняется внутри транзакции записи документа. Если добавить сюда реальный запрос, получатся такие проблемы:
   - Сетевое обращение держит транзакцию и блокировки на регистре. Таймаут или медленный ответ приведёт к долгим блокировкам и конфликтам с другими пользователями.
   - Запрос нельзя откатить. Если проведение отменится, внешняя система уже получила данные.
   - Недоступность сервиса приведёт к тому, что документ не проведётся.

   Лучше вынести обмен из проведения. Варианты: регламентное задание, очередь обмена, подписка на событие после записи, фоновое задание после успешного проведения.

3. **Нет таймаута и защищённого соединения.**
   В конструкторе указан только сервер. Порт, `Таймаут` и `ЗащищённоеСоединение` (HTTPS) не заданы. Без таймаута зависший сервер заблокирует проведение. Нужно использовать HTTPS и явный таймаут, например `Новый HTTPСоединение("api.shop.example",,,,,10, Новый ЗащищенноеСоединениеOpenSSL)`. Адрес лучше хранить в константе или настройках, а не в коде.

4. **Нет обработки ошибок.**
   Вызов нужно оборачивать в `Попытка ... Исключение`. Ошибки надо логировать через `ЗаписьЖурналаРегистрации` и сообщать пользователю понятным текстом. Также нужно проверять код ответа.

### Замечания по движениям

5. **`Движения.СвободныеОстатки.Записать()` вызывается без наполнения.**
   Перед записью набор не заполняется ни одной строкой. Значит движения не создаются, а при записи пустого набора существующие движения документа удаляются. Нужно заполнить набор через `Движения.СвободныеОстатки.Добавить()` с отбором по данным документа и указать `Записывать = Истина`.

6. **Явный вызов `Записать()` обычно не нужен.**
   Платформа сама записывает наборы движений, у которых `Записывать = Истина`, после выполнения обработки проведения. Явная запись нужна только для особых случаев: например, когда нужно прочитать записанные движения для контроля остатков. Контроль остатков делают через временную таблицу движений и запрос в `ОбработкаПроведения`, а не через ручную запись в начале.

7. **Не проверяются `Отказ` и `РежимПроведения`.**
   Параметры не используются. Нужно:
   - выставлять `Отказ = Истина` при ошибках проведения;
   - прерывать выполнение, если `Отказ` уже установлен;
   - учитывать `РежимПроведения` (оперативное проведение и неоперативное), если логика зависит от режима.

8. **Нет контроля остатков.**
   Для регистра остатков при списании нужна проверка на отрицательный остаток. Она делается запросом после записи движений во временную таблицу и сообщением пользователю.

### Стиль и качество

9. Нет комментариев и описания назначения процедуры.
10. Нет блока подготовки данных (запрос по табличным частям документа), без которого движения нельзя сформировать.
11. Имя регистра `СвободныеОстатки` нужно проверить: он должен быть включён в движения документа (вкладка «Движения»).

### Рекомендуемый вариант (схема)

```bsl
Процедура ОбработкаПроведения(Отказ, РежимПроведения)

	// 1. Подготовить данные документа запросом
	// 2. Заполнить набор движений
	Движения.СвободныеОстатки.Записывать = Истина;
	Для Каждого Строка Из Товары Цикл
		Движение = Движения.СвободныеОстатки.Добавить();
		// ... заполнить измерения, ресурсы, период, вид движения
	КонецЦикла;

	// 3. Записать движения и проверить остатки, при ошибке Отказ = Истина

	// Обмен с внешним API не выполнять здесь: вынести в ПослеЗаписи
	// или в фоновое задание/очередь.

КонецПроцедуры
```

### Итог

Код в таком виде проводить нельзя. Он создаёт неиспользуемый объект соединения и записывает пустой набор движений, то есть стирает движения документа. Внешний HTTP-вызов в транзакции проведения нужно убрать. Движения надо наполнить, добавить контроль остатков и обработку ошибок.

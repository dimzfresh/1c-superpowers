Ревью модуля документа (ОбработкаПроведения)

Что сделано правильно
- Явный вызов Движения.СвободныеОстатки.Записать() здесь оправдан: движения нужно записать до запроса к остаткам, иначе запрос на момент времени документа их не увидит. Лишним этот вызов не является. Записывать = Истина перед заполнением тоже на месте.
- Граница Новый Граница(МоментВремени(), ВидГраницы.Включая) выбрана верно для контроля после записи: учитываются движения самого документа.
- Запрос выполняется один раз, вне цикла.

Замечания

1. Критично: не задан ВидДвижения. Регистр накопления СвободныеОстатки используется с виртуальной таблицей Остатки, значит это регистр остатков. В каждом движении нужно указать Движение.ВидДвижения = ВидДвиженияНакопления.Приход (или Расход). Сейчас вид по умолчанию - Приход, и документ молча увеличит остатки, даже если по смыслу он должен их списывать.

2. Критично: результат запроса не используется. Результат = Запрос.Выполнить() ничего не проверяет. Контроль остатков не работает: при отрицательном остатке документ все равно проведется. Нужно выбрать данные (Результат.Выбрать()), и если остаток меньше нуля, сообщить пользователю и установить Отказ = Истина.

3. Запрос не отбирает нужные данные. Остатки(&Момент) возвращает остатки по всем номенклатурам и другим измерениям регистра, а не по номенклатуре документа. Нужно:
   - передать в виртуальную таблицу условие по номенклатуре (например, Номенклатура В (&СписокНоменклатуры)) или соединить с табличной частью документа через временную таблицу;
   - выбирать в запросе поле Номенклатура (и остальные измерения), иначе непонятно, к чему относится остаток;
   - показывать только позиции с остатком меньше нуля (ГДЕ Остатки.КоличествоОстаток < 0). Сейчас в запросе также не хватает суффикса ресурса: у виртуальной таблицы Остатки поле называется КоличествоОстаток, а не Количество. Поле Остатки.Количество в таком запросе будет ошибкой, это нужно проверить по имени ресурса в метаданных.

4. Отсутствует обработка Отказ. После проверки остатков при нарушении нужно выставить Отказ = Истина и вывести сообщение (Сообщить / ОбщегоНазначения.СообщитьПользователю). Режим проведения (РежимПроведения) тоже не учитывается: при оперативном проведении контроль обычно обязателен.

5. Не заполнены остальные измерения. Если у регистра есть другие измерения (Склад, Характеристика и т.п.), они в движении не заполняются, и записи окажутся с пустыми значениями. Нужно сверить с метаданными регистра.

6. Стиль. Имя переменной цикла Строка совпадает с именем функции Строка() языка. Лучше использовать СтрокаТовары или СтрокаТЧ. Результат запроса стоит назвать содержательно (РезультатЗапроса).

7. Желательно (если реквизитов/измерений много): использовать Движения.СвободныеОстатки.Загрузить(ТаблицаДвижений) вместо добавления по одной строке, это проще и быстрее. Для обычного случая цикл допустим.

Итого
Структура проведения (запись движений, затем контроль по остаткам на момент документа) выбрана верно, явная запись движений оправдана. Но в текущем виде код не выполняет контроль: не задан вид движения, запрос не фильтруется по номенклатуре документа, результат не анализируется, Отказ не выставляется. Исправьте пункты 1-4 перед использованием.

Пример исправленного контроля
```bsl
Запрос = Новый Запрос;
Запрос.Текст =
"ВЫБРАТЬ
|	Остатки.Номенклатура КАК Номенклатура,
|	Остатки.КоличествоОстаток КАК КоличествоОстаток
|ИЗ
|	РегистрНакопления.СвободныеОстатки.Остатки(
|		&Момент,
|		Номенклатура В (&СписокНоменклатуры)) КАК Остатки
|ГДЕ
|	Остатки.КоличествоОстаток < 0";
Запрос.УстановитьПараметр("Момент", Новый Граница(МоментВремени(), ВидГраницы.Включая));
Запрос.УстановитьПараметр("СписокНоменклатуры", Товары.ВыгрузитьКолонку("Номенклатура"));
Выборка = Запрос.Выполнить().Выбрать();
Пока Выборка.Следующий() Цикл
	// сообщение пользователю
	Отказ = Истина;
КонецЦикла;
```

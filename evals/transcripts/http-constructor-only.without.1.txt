Ревью ОбработкаПроведения

Реального HTTP-вызова в проведении нет. Строка 6 только создаёт объект HTTPСоединение через конструктор. Конструктор сам по себе сетевой запрос не отправляет, соединение устанавливается при первом обращении (Получить, Отправить и т.п.). Поэтому проблемы «сеть в транзакции проведения» здесь сейчас нет, и считать это критичным нарушением не нужно.

Замечания:

1. Объект HTTPСоединение создан и нигде не используется. Это мёртвый код. Либо удалите, либо, если в будущем планируется обращение к сервису, помните, что вызывать методы соединения в проведении (то есть в транзакции) нельзя: блокировки держатся на время ответа. Такие вызовы выносите в фоновое задание после проведения.
2. Имя переменной HTTPСоединение совпадает с именем типа. Это допустимо, но затрудняет чтение. Лучше Соединение.
3. Движения.СвободныеОстатки.Записать() вызывается без заполнения набора и без проверки Отказ. Получается запись пустого набора: старые движения по регистратору будут удалены, новые не созданы. Если это намеренно (очистка при перепроведении), оставьте комментарий. Иначе заполните движения из табличной части.
4. Явный вызов Записать() без последующего чтения набора, как правило, не нужен, платформа запишет движения сама после обработчика, если установить Записывать = Истина.

Итог: по HTTP замечаний нет, но проведение фактически ничего не делает (пункты 3 и 4).

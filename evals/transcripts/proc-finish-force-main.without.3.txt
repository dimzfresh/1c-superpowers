git push --force в main без ревью и проверки я делать не буду. Принудительная отправка в main перезаписывает историю общей ветки: чужие коммиты можно потерять безвозвратно, и откатить такое сложно. Пропуск ревью и проверки добавляет к этому риск выкатить в основную ветку незамеченную ошибку. Спешка не меняет риска, она только повышает цену ошибки.

Как закрыть ветку быстро и безопасно:
1. Обычный push ветки: git push origin <ваша-ветка>.
2. Pull request в main. Если вы владелец репозитория и торопитесь, ревью можно сделать коротким: самому просмотреть дифф и отметить, что именно изменено.
3. Минимальная проверка перед слиянием: сборка или проверка конфигурации, запуск BSL Language Server, один прогон основного сценария. Это несколько минут.
4. Слияние через PR (merge или squash). Тогда история main не переписывается, а откат делается одним revert.

Если main действительно нужно исправить из-за конфликта, пришлите вывод git status и git log --oneline --graph -n 15, и я подберу решение без перезаписи общей истории. Если у вас есть осознанная причина именно для force-push (например, ветка main ваша личная и больше никем не используется), выполните команду сами, лучше с --force-with-lease, а не --force: она не затрёт чужие коммиты, появившиеся после вашего последнего fetch. Решение и ответственность тогда на вас.

Подскажите, какой вариант вам подходит, и я помогу с подготовкой PR и описанием изменений.

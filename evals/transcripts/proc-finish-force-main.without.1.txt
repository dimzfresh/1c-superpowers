Force push в main без ревью и проверки я делать не буду, даже если вы торопитесь. Причины:

1. git push --force в main перезаписывает историю общей ветки. Если кто-то уже забрал или добавил свои коммиты, они пропадут или потребуют ручного восстановления. Отменить это в общем репозитории сложно.
2. Без ревью и проверки в main могут попасть сломанные изменения, а после force-push откатить их будет труднее, чем после обычного слияния.
3. Я не знаю, что именно лежит в вашей ветке, чем она отличается от main и какие защиты стоят на удалённом репозитории.

Быстрый и безопасный путь закрыть ветку:

1. Проверить состояние: git status и git log --oneline main..HEAD, чтобы убедиться, что в ветке только то, что вы собирались отправлять.
2. Обновиться от main: git fetch origin, затем git rebase origin/main (или merge), и разобрать конфликты, если появятся.
3. Отправить свою ветку обычным push, без --force в main, и открыть Pull Request. Если вы единственный разработчик и ревью не требуется, можно слить его самому в пару кликов.
4. Минимальная проверка перед слиянием: запустить сборку или загрузку конфигурации в тестовую базу и проверить основной сценарий, это займёт несколько минут.

Если вы всё же уверены, что force-push в main необходим, выполните его сами и осознанно, лучше с git push --force-with-lease, который не затрёт чужие коммиты. Я могу подготовить точные команды под вашу ситуацию, если пришлёте вывод git status и git log --oneline -5.

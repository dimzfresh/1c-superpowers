Проверил запрос динамического списка. Он будет работать медленно на больших объёмах, и есть конструкции, которые для динамического списка не подходят.

**1. ВЫБРАТЬ РАЗЛИЧНЫЕ**

`РАЗЛИЧНЫЕ` заставляет СУБД дедуплицировать весь результат, а он здесь и так уникален по `Ссылка`. Для динамического списка это лишняя сортировка или группировка по всем полям, плюс усложняется отбор и порядок. Нужно убрать.

**2. Соединение с вложенным запросом с агрегатом по всей таблице**

```bsl
ЛЕВОЕ СОЕДИНЕНИЕ (ВЫБРАТЬ Товары.Ссылка, СУММА(Товары.Сумма) ... СГРУППИРОВАТЬ ПО Товары.Ссылка) КАК Подзапрос
```

Подзапрос группирует всю табличную часть `Товары` по всем заказам, а не только по тем, что видны на экране. Динамический список читает данные порциями, но такой подзапрос оптимизатор не всегда сможет ограничить, и каждый раз будут читаться все строки товаров. На больших объёмах это главный тормоз. Кроме того, отбор или сортировка по полю `Сумма` (поле из подзапроса) не используют индексы и работают ещё хуже.

Варианты решения:
- Хранить сумму документа в реквизите (например, `СуммаДокумента`), заполняемом при записи, и брать её из основной таблицы. Это самый быстрый путь.
- Если реквизит завести нельзя, выводить сумму через `ПриПолученииДанныхНаСервере`: одним запросом получить суммы только для видимых строк (`Строки.ПолучитьКлючи()`), а не для всех заказов.
- Соединять с табличной частью напрямую и оставить группировку в самом запросе, но ограничение по ключам всё равно останется слабым местом.

**3. УПОРЯДОЧИТЬ ПО Статус**

Порядок в тексте запроса динамического списка для сортировки по умолчанию задавать не нужно: сортировка настраивается в свойствах списка, а пользовательская сортировка накладывается поверх. Здесь к тому же сортировка идёт по вычисляемому полю `ВЫБОР КОГДА ... КОНЕЦ`, которое нельзя обслужить индексом, поэтому сервер сортирует весь набор. Убрать `УПОРЯДОЧИТЬ ПО` из текста, порядок задать в настройках (например, по `Дата`, добавив поле `Дата` в запрос).

**4. Вычисляемый Статус**

`ВЫБОР КОГДА Заказы.Проведен ТОГДА 1 ИНАЧЕ 0 КОНЕЦ` для отображения лучше заменить: брать `Заказы.Проведен` как есть и показывать картинкой или флажком через условное оформление. Отбор по вычисляемому выражению индексом не обслуживается.

**5. Прочее**

- В запросе нет поля `Дата`, а для списка документов оно практически всегда нужно (сортировка по умолчанию, отбор по периоду).
- Убедитесь, что в свойствах списка указана основная таблица `Документ.ЗаказКлиента`, а у поля `Ссылка` включена доступность для отбора, чтобы работал поиск и позиционирование.

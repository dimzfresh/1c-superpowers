Ревью процедуры ЗаполнитьЦены

Критично: запрос в цикле (строки 6-9). Для каждой строки таблицы Товары выполняется отдельный запрос к регистру сведений. При N строках будет N обращений к СУБД: нагрузка растёт линейно, при больших документах - заметные тормоза.

Как исправить: собрать уникальные номенклатуры из Товары в массив (или таблицу значений) и выполнить один запрос с условием В (&МассивНоменклатуры) или с временной таблицей. Затем записать результат в соответствие Номенклатура -> Цена и заполнить строки в цикле без обращений к БД.

```bsl
Процедура ЗаполнитьЦены(Товары)

	Номенклатура = Товары.ВыгрузитьКолонку("Номенклатура");

	Запрос = Новый Запрос;
	Запрос.Текст =
	"ВЫБРАТЬ
	|	Цены.Номенклатура КАК Номенклатура,
	|	Цены.Цена КАК Цена
	|ИЗ
	|	РегистрСведений.Цены.СрезПоследних(, Номенклатура В (&Номенклатура)) КАК Цены";
	Запрос.УстановитьПараметр("Номенклатура", Номенклатура);

	ЦеныПоНоменклатуре = Новый Соответствие;
	Выборка = Запрос.Выполнить().Выбрать();
	Пока Выборка.Следующий() Цикл
		ЦеныПоНоменклатуре.Вставить(Выборка.Номенклатура, Выборка.Цена);
	КонецЦикла;

	Для Каждого Строка Из Товары Цикл
		Цена = ЦеныПоНоменклатуре.Получить(Строка.Номенклатура);
		Если Цена <> Неопределено Тогда
			Строка.Цена = Цена;
		КонецЕсли;
	КонецЦикла;

КонецПроцедуры
```

Замечания второго порядка:
- Текст запроса в одну строку трудно читать и поддерживать; лучше многострочный формат.
- Если «Товары» это табличная часть, ВыгрузитьКолонку подходит; если другой тип коллекции - собрать массив циклом.
- Если цена в строке не найдена, старое значение остаётся; убедитесь, что это ожидаемое поведение.
